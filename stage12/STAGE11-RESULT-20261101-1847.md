# Stage11 真机结果：模式断言发生于 validator 之前

用户提供的两张 18:47 照片可直接读到 Stage11 摘要：

```text
CDX11 pid=26 match=1 busy=0 n=1 drop=0
CDX11 first e=6 c0=1 c1=19f3d0744
CDX11 last e=6 off=1 sl=0 c0=1 c1=19f3d0744
CDX11 st=10 fail=0 reg=1 cl=4 rc=0
CDX11 val=0 ok=0 why=0 cp=0 rc=ffffffff
CDX11 ret=0 vs=0
```

重点校正：PC 是 **19f3d0744**；st 是 **10**。不是 st=0，也不是 19f3d3744 / 19f3d3328 / 19f3d3e24。无需再为读准这个地址重复刷诊断镜像。

原版缓存已独立确认：这是 FBSDisplayMode 初始化的主动 BRK，失败文本 `FBSDisplayMode cannot be configured as requested : %@`；基址 19f3c1000，偏移 f744，方法内 +244。详见 DISPLAY-MODE-RESULT-20261101-1820.md 与原反汇编。

- st=10/fail=0/reg=1：按实际 Probe 定义，显示生命周期到达启动成功且注册服务的阶段。
- cl=4/rc=0：累计观察到 4 次 newUserClient，最近返回成功；不能据此推断每个调用者是谁或所有模式查询成功。
- val=0/cp=0/ret=0：没有观察到 owned validator、复制和完成路径调用。不能把它解读成复制已失败，也不严格等于用户态没有发送过任何请求。
- cp=0 时 rc=ffffffff 是初始值 -1，不是一次实际复制的错误码。
- vs=0 只说明没有观察到软件通知计数，不足以证明硬件/时钟故障。
- match=1/busy=0/n=1/drop=0：此次摘要成功匹配 SpringBoard，记录没有发生锁竞争丢失。

构建关联：dsh 记录 18:44:46 启动 stage11 内核 `7f3b413b73fdece9fea56f7199b0d8cf39e0ded2a767d44240074bff56fbe3ef`，CI 41297967470；本会话核对了交回 build-report，其 backend 仍是 stage10 的 0ab790...，Probe 为 5c1ff1...。照片与该记录一致，照片本身不是镜像散列的测量。

## 本轮新增静态证据

从原始 SystemOS 仅提取原版 dyld 子缓存 .03，UUID 与已验证主缓存的 subcache entry 对应。SHA256：`1d3387ecfe16d74c420e02257edccbba36073cbc0c909de11a353a59d9fc967c`。原图与缓存没有改写。

CADisplayMode 的原版代码表明：

1. `_initWithMode:display:rates:` 把 mode 保存在内部结构第一个 QWORD；宽高分别从 mode 低 14 位、从 bit14 起 14 位解出。
2. refreshRate 在 mode 不为全 1 时，从 bit29 起的 25 位解码成定点速率，再做舍入；特殊全 1 mode 则经另一条时间间隔路径求倒数。
3. preferredScale 在没有显式覆盖时还有自身回退逻辑。因此不能只凭未发布 IOMFBDisplayRefresh 就宣布刷新率为零，也不能盲设物理 DPI。

原指令保存于 ca-mode-init.asm、ca-mode-refresh.asm、ca-mode-scale.asm。下一版需要取得实际非法 FBSDisplayMode 对象中的各项值，才能把 packed mode 的来源与本机症状对应。

## Stage12 已实现的候选

- 保留 Stage11。在已核验的这个 fatal PC、ASLR off/slide0、SpringBoard 名字及 saved PC 均匹配时，用已核对的原 XNU copyin 接口只读对象 +8 的 64 字节，汇总 width/height/preferredScale/scaleOverride/refreshRate/gamut/HDR/rotation。copyin 失败、PID 不匹配或锁忙会显式显示无有效值，不以旧值充数。它不是通用内存转储或对其他任务的读取。
- 修正 60Hz 显式属性发布缺口，单独由 `luming-display-refresh-publish=1` 开启：在现有 sheng-vsync=60 时调用已经字节审计的原版属性发布函数。默认不开，便于同内核做对照。只提供软件调度/原 mode 属性，不宣称真实面板 vblank。
- 不改 FBS 用户态指令，不放开验证器，不虚构模式/DPI，不改 super/分区或刷机。

以上是可审查的源码候选，尚未完整编译或真机验证。60Hz 属性发布是否能解除这个 FBS 模式断言，当前仍是待测假设；对象参数诊断可在它未解决时直接定位非法字段。
